# 项目与工具使用说明

这是源码修改说明。编辑源码、运行独立单元测试不需要安装完整语音运行环境；安装或更新实际使用的 MeloMate 后，新界面与后端才会生效。

## 工作目录

不再提供「项目与工具」设置栏目。新用户直接使用当前角色工作区，例如当前角色为小可，内置文件工具的工作范围就是：

```text
MeloMate/workspace/小可/
```

旧浏览器保存过的项目子目录会继续生效，例如 `projects/site` 仍限定在 `workspace/小可/projects/site/`，升级不会自动扩大范围。此版本**不支持把任意电脑绝对路径直接设为项目**。源码仓库本身不会自动成为角色的工作目录。

模型传入的读写、搜索、检查、运行目录会统一映射到所选目录；`../`、绝对路径、其他角色和目录链接跳转会被拒绝。创建成果包、回收站恢复和页面状态读取也受同一范围限制。文件工具返回的路径可以直接用于后续工具调用，不会重复加项目前缀。

旧的目录与服务数据仍按角色保存在原浏览器中，换浏览器或清除存储不会自动带过去。对话与角色记忆仍按角色保存；项目工具记录按角色和项目目录分别保存，不是每个项目单独一份完整聊天历史。

## 模型决定调用，工具默认允许

模型根据对话选择工具，已接入工具统一允许调用，不再逐次询问。问号、「如何」等词不决定是否提供写文件或提醒工具。工具已开放也不意味着每句聊天都应该调用它。

- 项目文件、记忆、提醒、运行代码、项目代码联网、PC 浏览器、已配置服务和外部工具均默认允许。
- 设置中移除整个项目与工具栏目，包括工具列表、项目子目录、服务编辑器、生成温度和输出上限。
- 旧浏览器保存的「询问／禁止」、单项权限、温度和输出上限自动清理；已有项目范围与服务连接保留。
- 程序仍检查项目目录、服务范围、参数和任务配置版本；切换配置前的旧调用不能在新配置下继续。
- 「停止当前任务」仍可取消当前对话。已发给外部服务的操作不保证可以撤回；容器命令还受独立超时限制，超时后需检查实际文件状态再重试。

工具结果、网页和项目文件属于资料，不能改变这些设置。项目聊天不会仅因网页自行报告 `agentShouldAct` 就启动后台操作；模型可在对话工具循环中读取状态并选择明确的页面动作。

每条模型回复的文字都可以双击：平时保持原有样式，鼠标移上时出现边框，双击后右侧切换到「回复详情」。左上角「返回」或 Esc 回到聊天，原聊天和滚动位置保留；键盘聚焦回复后按 Enter/空格也可打开。详情显示 API 实际返回的思考内容、该轮工具记录、最近截图和本轮更新的计划。未返回思考内容时明确说明，不生成替代思考。语音分成多段展示的同一轮回复共用该轮记录。生成过程中详情实时更新，只有当前运行的任务提供停止按钮。

详情记录只保存在当前页面内存中，刷新页面后不恢复；最多保留 120 轮并有总大小限制。单轮思考展示最多 250,000 字符、工具摘要最多 100 条，超长思考会提示显示截取；这不截断 API 的当前轮协议回传。旧会话、无记录或已清理的回复显示暂无记录。迟到消息、其他角色消息以及没有轮次标识的全局日志不会混入当前回复。

最近 100 条经过常见凭据模式脱敏的结果摘要仍保存在 `backend/cache/task-progress/`，用于模型继续任务；摘要可能包含项目文本，图片不写入该日志。历史成功不能替代当前状态验证。

## 写代码与验证

`validate_workspace_project` 可以检查 Python、JavaScript 和 JSON 语法，返回具体文件错误，不执行项目代码。JavaScript 检查需要可用的 Node.js；其他格式、依赖检查和实际交互不由这个工具验证。

`get_workspace_runtime` 检查隔离执行环境是否可用。`run_workspace_command` 以参数数组运行测试或构建，例如：

```json
{"persona":"小可","cwd":"","argv":["python3","-m","unittest","discover"],"timeout_seconds":120}
```

执行使用本机已准备好的 Docker Linux 容器，只挂载当前项目目录，不传入宿主凭据，不开放 Docker socket，并限制内存、CPU、进程数和执行时长。单次命令的网络参数默认关闭；模型可以选择 `network=true` 开启，无需额外确认。联网容器可访问外部网络，也可能访问局域网服务，并不具有仅访问某个域名的限制。宿主私有 `.control` 和 `.trash` 在容器中被只读空挂载遮盖。没有容器环境时会明确返回未执行，**不会转到宿主命令行运行，也不会自动安装 Docker 或下载镜像**。

需要代码执行时，开发者可以另外准备 Docker，并主动构建仓库提供的基础镜像：

```text
docker build -t melomate-runner:local backend/runner
```

这一步会下载构建依赖，此次源码修改并未执行。基础镜像提供 Node.js、Python、pip、venv、pytest、Git。模型可选择联网执行，把任务所需项目依赖安装进项目目录，例如 `python3 -m pip install --target .deps requests`，或 `npm install --cache /tmp/npm`；仍须遵守用户「不下载」等明确限制。执行 Python 时需通过项目代码或启动参数正确引用 `.deps`。依赖也可预先放入自定义镜像。可通过 `MELOMATE_RUNNER_IMAGE` 指定已有镜像。容器中的 Python 命令是 `python3`。

## PC 通用工作工具

默认允许只省去了工具许可步骤，不会自动准备软件和连接信息。普通聊天不需要以下可选工作环境：

| 条件 | 通俗解释 | 何时需要 |
|---|---|---|
| Docker 与执行镜像 | 给项目代码提供一个独立的运行环境；需要本机已安装、启动 Docker，并准备执行镜像 | 实际运行项目命令、测试或构建 |
| 浏览器组件 | 主安装流程已包含 Playwright；优先复用 Edge 或 Chrome，没有可用浏览器时由安装流程下载 Chromium | 使用浏览器工具；无需单独准备 |
| 服务地址 | 程序或设备接口的连接位置，例如 `http://127.0.0.1:9000`；对应服务必须实际运行且可达 | 调用已连接的程序、API 或设备 |
| 凭据 | 服务要求的 API Key、Token 等身份凭证；不要求认证的服务可以不填 | 调用需要认证的服务 |

本地 PC 工具共 18 个（含 3 个角色记忆工具和 1 个会话状态工具），接入同一个模型工具调用循环。加上内置工作区与日常工具，默认共 47 个工具定义，另有屏幕查看与本地启动器的可选工具。定义存在不表示运行环境已就绪。

| 工具 | 用途 |
|---|---|
| `get_pc_capabilities` | 检查真实环境和能力，不凭空假设已经安装 |
| `get_session_state` | 查看当前角色的会话、实际变化通知、项目、计划和近期工具结果；只读 |
| `list_connected_services` / `request_connected_service` | 查看并调用已配置的 HTTP 服务，适用于本地程序、公开 API、设备等 |
| `copy_workspace_item` | 非覆盖地复制文件或目录 |
| `archive_workspace_items` / `extract_workspace_archive` | 创建/解压 ZIP，限制大小并拒绝目录越界与链接 |
| `download_workspace_file` | 将公共网络文件下载到新的项目路径，不执行下载内容 |
| `browser_open` / `browser_open_workspace` | 打开公共网页或预览当前项目 HTML |
| `browser_read` / `browser_action` / `browser_close` | 获取页面文字、元素、截图和 JS 错误；执行一次点击、输入、选择、按键或滚动；关闭标签页 |
| `read_work_plan` / `update_work_plan` | 由模型按需保存与恢复任务计划；不会自动执行计划 |
| `read_memory` / `search_memory` / `edit_memory` | 读取、检索、更新当前角色的文本记忆，有真实对话来源与版本校验 |

模型自行决定工具组合、参数、顺序、是否重试或询问。普通聊天无需调用工具或写计划。需要解决问题时，模型可根据实际情况查资料、检查项目、写代码、运行测试、查看网页并继续修正；没有同名专用工具不等于无法推进。账号、真实设备协议、许可证、用户选择等未知条件不能靠编造补足。

计划保存在 `backend/cache/work-plans/`，按角色和项目区分。它和调用记录属于历史资料；恢复时仍需核实当前状态。界面显示模型保存的计划，不把其中的“已完成”当作独立验证。

### PC 浏览器的准备与范围

浏览器组件 `backend/pc-tools-requirements.txt` 已纳入主依赖，运行 `setup-windows.bat` 会一起准备。安装与聊天运行共用浏览器查找规则，优先使用已安装的 Edge，其次 Chrome，再使用已准备好的 Chromium。如果均不存在，主安装流程下载 Chromium，无需再运行第二个安装程序。旧安装也可运行 `setup-pc-tools.bat` 单独补齐；它同样可能下载 Chromium。聊天过程不下载或安装浏览器。本次源码修改没有运行这些安装脚本。

浏览器使用独立、临时的会话，不接管个人浏览器的登录资料；最多 5 个标签页，关闭会话或更换角色/项目时销毁。返回的截图只给支持视觉的模型提供图像理解能力。页面元素、结果和脚本错误由模型自行分析，点击完成不代表网站业务操作成功。

浏览器支持公共 HTTP(S) 网站和静态项目预览；网络请求经过公共地址检查和固定 IP 连接。局域网接口使用单独配置的服务工具。WebSocket、Service Worker 和隐式下载被关闭，部分复杂网站、登录流程或跨框架操作可能不兼容。它不是 Windows 桌面软件的通用鼠标键盘控制器，也不会自动启动项目后端服务。工程接口参考 [Playwright 临时浏览器上下文](https://playwright.dev/python/docs/api/class-browsercontext)和[浏览器渠道](https://playwright.dev/python/docs/browsers)。

### 通用服务连接

「连接服务与 API」原来用于接入电脑上的程序、局域网设备或其他 HTTP 接口，例如调用 `http://127.0.0.1:9000/api/`。这是外部工具连接，与聊天模型的 API 地址和密钥不同；普通聊天无需配置。该编辑器现已随项目与工具栏目移除，原浏览器已保存的服务仍可恢复并被模型调用。当前没有新增或编辑 HTTP 服务连接的界面，也不会凭空知道新设备地址或密钥；开发者可通过下文 MCP 配置扩展工具。

已经保存的服务密钥仍在 Windows DPAPI 凭据存储中，不因界面移除而删除，不进入聊天、模型参数、项目源码或浏览器存储。凭据绑定角色、服务 ID 和地址，改变地址不会把原有密钥带到新主机。支持无需认证、Bearer Token 和自定义认证请求头；尚未内置 OAuth 登录、MQTT 或厂商 SDK。这些接入可由模型准备代码并通过适当的运行环境或 MCP 扩展实现。

服务调用不会跟随重定向，也不会替模型认定任务成功。返回 HTTP 状态和实际内容后，模型决定是否还需查状态、修代码或补充条件。公共下载工具不会访问局域网地址；它只保存文件，不安装软件。

## API 与 MCP

DeepSeek 等 OpenAI-compatible 接口的 `reasoning_content` 作为独立事件传给详情页，不朗读、不作为聊天正文或记忆证据。当前工具循环完整保留 assistant 消息的思考、正文和工具调用，再配对回传真实工具结果；连接提前结束或输出截断时不执行未完成的工具请求。普通接口没有思考字段时照常聊天。

跨轮协议保存在已有 `.history.sqlite3` 的独立表中，不新增需要用户维护的文本文件。仅恢复同一角色、同一 API 地址与模型、同一记忆版本且正文未被删改的完整记录，不进入记忆整理、全文检索或普通历史接口。最多保留最近 120 条聊天范围内的记录，单轮缓存和单次历史恢复各限 4 MiB；超出时整个记录不回放，不截断工具配对。旧版对话、缓存不可用或更换模型时，没有捕获到的历史思考使用空字段兼容 DeepSeek，不编造原始思考。记忆删改、清空或当前轮修改记忆后，不回传涉及旧版本的协议内容。

原生 Claude 返回的 thinking 文本也可显示；工具循环保留其签名与 redacted thinking 块供协议回传，签名和隐藏块不展示为思考文字。这不会强行开启服务商原本未开启的思考模式。接口行为参考 [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。第三方网关实现可能不同，需要实际接入验证。


原生 OpenAI-compatible 和 Claude 工具循环保留完整嵌套参数结构，多段文本、结构化结果和可支持的图片都会回送模型。图片理解仍要求所选模型支持视觉。多个内置只读工具最多并行 4 个；修改和外部工具按顺序执行。网络查询后，模型仍可在当前项目范围内继续读文件、修改并验证。

OpenAI-compatible API 明确报告不支持工具时，会切换为 JSON 文本调用协议；这依赖模型遵守格式，不能保证与原生调用同样稳定。调用截断不会被当成完整操作执行。API 自身的上下文长度、输出限制和模型能力仍然存在。

`backend/mcp_servers.json` 可配置 stdio 服务或 Streamable HTTP 服务。源代码未提供该文件时自动注册内置工作区和日常工具。以下是无凭据示例，需要自行替换地址、确认服务可信后使用：

```json
{
  "mcp_servers": {
    "my-tools": {
      "url": "http://127.0.0.1:9000/mcp",
      "enabled": true,
      "timeout": 60
    }
  }
}
```

外部工具使用服务名与工具名生成的唯一别名，避免同名覆盖。重启后发现配置中显式启用的服务，工具统一允许，调用过程可在聊天区的任务记录查看。旧的角色配置 `mcp_enabled_servers` 仍兼容。

接口对照仓库依赖范围内的 [MCP Python SDK 1.28 客户端源码](https://github.com/modelcontextprotocol/python-sdk/blob/v1.28.0/src/mcp/client/session.py)及其 [HTTP 传输实现](https://github.com/modelcontextprotocol/python-sdk/blob/v1.28.0/src/mcp/client/streamable_http.py)核对；命令工具同时传递 SDK 请求超时，避免仅增加外层等待时间。

外部 MCP 服务运行在它自己的权限范围，**不会因为当前选择了项目目录就自动被限制在该目录**。本地 stdio 服务是开发者配置的宿主程序；远程服务是网络连接。不要把项目文件范围误认为这些服务的隔离边界。凭据不应提交进源码示例。

## 聊天与记忆

通用任务指导只在进入工具循环后加入，普通聊天使用更短的说明。默认小可人设只有名字，不预设关系发展或强制表达方式。用户定制人设和聊天产生的记忆均为可编辑文本，见 [人设与记忆说明](MEMORY.md)。

当前会话、文件变化和实际工具结果交给同一个聊天模型处理；主动说话开关也控制文件变化引起的回应机会，见 [会话与真实状态说明](COMPANION.md)。

界面不再提供生成温度和单次输出上限。DeepSeek 等 OpenAI-compatible 聊天请求不再发送 MeloMate 固定的 `max_tokens=8192`，由服务商使用自身默认值与限制；省略参数不代表无限输出，也不一定自动使用服务商最大值。原生 Claude 协议要求 `max_tokens`，程序优先查询模型元数据中的最大输出值；旧 SDK 或兼容网关无法提供时仍使用 8192 作为兼容值，避免缺少必填参数。参考 [Claude Messages](https://platform.claude.com/docs/en/api/messages/create) 和 [模型元数据](https://platform.claude.com/docs/en/api/models/retrieve)。

记忆整理使用当前聊天模型与同一 API 服务、凭据，按新对话量触发，短闲聊延后、失败后冷却重试，不需另配模型。具体阈值见记忆说明。模型配置自身的温度默认值仍生效，Claude 的温度按其适配器范围最高限制为 1。后台记忆大小、工具轮数、任务超时等独立限制不属于聊天输出设置。

移除了旧的语义筛选模型请求和对应设置。现在用 SQLite 文本索引检索历史，模型按需换关键词查询；不是向量语义搜索。后台整理仍有额外 API 用量。实际聊天与编程质量需要用所选模型、同类任务实测。

## 源码验证

不安装完整后端的测试：

```text
python -B -m unittest discover -s backend/tests -p test_project_runtime.py
python -B -m unittest discover -s backend/tests -p test_text_memory.py
python -B -m unittest discover -s backend/tests -p test_pc_work_tools.py
python -B -m unittest discover -s backend/tests -p test_daily_tool_executor_policy.py
npm run check
npm run test:security
npm run test:runtime
npm run build
```

新增测试使用模拟 MCP 和模型响应，以及本机临时 HTTP 测试服务，验证权限、目录映射、ZIP 处理、凭据注入/遮盖、重定向处理、任务恢复、浏览器请求网关、连接生命周期、参数格式和结果处理。测试凭据存储使用替代加密器验证数据流，不代替 Windows DPAPI 实机验证。尚未完成真实模型、语音、浏览器本体或 Docker 端到端测试。完整后端测试需要该后端的运行依赖。
