# 通用 Agent 改造清单

2026-09-11 源码核对后的实施方案。本文描述待实现工作，不表示这些能力已经可用。

## 目标与范围

用户说明目标后，模型能查明条件、选择方法、执行、根据失败修正并验证结果。能自行解决的技术步骤由模型推进；缺少不可自行取得的信息、物理操作或超出现有授权时，才提出具体的必要请求。普通聊天不自动变成工作任务，人设和关系不增加成长要求。

“合格”以明确任务范围内可重复的实测为依据，不以工具数量或一次演示成功判断，也不承诺适配所有设备和服务。源码测试、模拟服务测试和真实模型端到端测试分别报告。

## 当前已具备与实际缺口

已有项目文件操作、搜索、浏览器、HTTP 服务、隔离执行、MCP 接入、计划保存、工具结果回传，以及角色记忆和会话状态。正常情况下模型可以连续选择工具并根据结果继续，不能描述成只能给建议。

目前主工具循环依附单轮聊天：普通路径最多 8 轮/16 次工具调用，项目写入路径最多 24 轮/64 次调用，整轮超时 600 秒。达到限制后返回需要用户说“继续”的提示，尚无通用任务检查点与自动分段续办机制。

`runtime_control.py` 已保存计划和有限的调用记录，但计划状态是模型自报，没有独立的目标验收记录。`project_runtime.py` 是限时容器命令，结束后清理容器；没有通用的长期进程托管。MCP 配置在初始化阶段发现，当前“刷新工具与记录”不重新加载新服务。当前项目范围只支持角色工作区下的子目录，并非任意 Windows 文件夹。

## 修改项目与验收标准

| 顺序 | 改什么 | 完成后用户能感受到什么 | 验收重点 |
|---|---|---|---|
| 1 | 通用任务状态与分段续办 | 一项工作跨多个工具循环继续，不需要反复说“继续” | 保存原始目标、进度、待解决问题、检查点、预算及停止原因；段末仍有可执行工作则在原授权内续办；预算耗尽、停止、需要输入时真正暂停 |
| 2 | 结果验证与失败恢复 | 写完、启动和实际可用被分别确认；遇到失败继续排查 | 模型选择与用户目标相关的验收方法，程序记录真实检查结果与产物版本；同样失败不能无限重试；超时和不明结果先查状态再决定是否重做 |
| 3 | 能力与环境发现 | 缺能力时能说清缺在哪里，优先复用已有软件和接口 | 区分工具已定义、环境存在、权限已给、服务可达和功能验证成功；返回可操作的错误信息，不把缺权限误判为缺软件 |
| 4 | 运行环境与依赖管理 | 接入代码能够准备运行条件并执行，不停在教程 | 保留容器执行，另提供显式启用的 Windows 本地执行入口；使用独立项目环境、可审查的安装计划和版本记录；禁止下载时明确使用已有环境或报告缺口，不暗中安装 |
| 5 | 长期进程管理 | 能启动自己写的服务、读日志、检查是否正常，并在需要时关闭或重启 | 有进程 ID、项目归属、端口、日志、健康检查和停止机制；断线、重连与应用退出行为明确；不误终止用户其他进程 |
| 6 | 扩展工具的发现与加载 | 模型写好连接程序后，能够把它接回当前任务继续使用 | 验证接口与参数结构、启动并检查服务、在安全调用边界刷新工具；加载失败保留旧版本；新工具的权限来自原有设置或新增授权，不能自行扩大 |
| 7 | 通用输入、服务与设备桥接 | 模型能读取新来源的文件或图像，并使用已接入的能力 | 图像等数据保留来源与采集时间，实际送到支持该输入的模型；文本模型明确说明限制；硬件控制按真实接口逐项验证，无接口时不声称可控 |
| 8 | 项目选择与任务界面 | 用户选一个文件夹，说目标，看进展，需要时停止 | 支持选定真实项目根目录；显示正在做、等待条件、已验证结果；工具选择由模型决定，程序不按“摄像头”等关键词硬编码业务流程 |
| 9 | 多类真实任务评测 | 能用结果判断这一版在哪些工作上可靠 | 覆盖建项目、调试、接入现有服务、自建服务并接回工具等任务；加入依赖缺失、接口失败、重启、权限拒绝、停止及模型提前结束等情况 |

Windows 本地执行需要明确说明：工作目录只是进程的起始位置，不能当作命令的安全隔离。项目文件工具继续执行目录边界校验；本地程序的实际访问范围由执行隔离和所授权限决定，不静默把容器失败转换成宿主执行。

## 实施顺序

第一阶段完成任务状态、预算内续办、验证证据和失败恢复。目标是已有工具能够把工作稳妥做完，避免先增加大量外部能力而缺乏可靠的执行流程。

第二阶段完成环境发现、可选本地运行、依赖准备、进程托管和受控工具加载。验收一个真实流程：发现没有所需接口 → 编写连接程序 → 在已授权环境运行 → 检查接口 → 接回当前任务 → 验证最终结果。优先用本地测试服务复现，之后用真实模型运行。

第三阶段补充文件/图像等输入桥接和特定设备适配，并完成多任务评测。设备只是应用场景，不把某个设备的一次成功等同于通用能力完成。

各阶段都验证普通聊天、角色切换、记忆修改和停止任务不会退化。模型继续负责选择步骤和工具，程序负责真实执行、权限、状态和结果记录，不新增控制角色性格的第二套机制。

## 数据与授权

用户的角色定制仍只编辑人设 MD 与 memory.md。任务、进程和扩展记录属于项目内部运行数据，界面自动管理，不让用户再维护多份角色记忆。重连后核实进程、文件和权限，不能仅因旧计划写着“执行中”就重放外部操作。

2026-09-12 已将现有接入工具统一允许，并移除界面权限选择；项目目录、服务范围和任务停止仍保留。后续新设备、账号或宿主执行仍需具备真实接口、运行环境与连接条件，不能把默认允许当作环境已经就绪。主动说话开关管理闲聊/事件回应，与用户已启动的工作任务分开，关闭主动说话不代表取消工作，停止任务也不等于退出聊天。

当前开发约束是不下载、不安装新依赖。可以先完成源码与使用已有环境的测试；缺少运行条件的端到端验证必须如实标为未完成，不能用模拟通过替代真实成功。本方案不自动提交或上传 GitHub。
