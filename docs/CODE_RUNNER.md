# 后台代码运行

执行器已经接入 MeloMate，复用部署时安装的 Python、Node.js，无需再安装运行服务或手工设置 Windows 权限。源码仓库不包含 Python、Node.js 二进制文件。

## 聊天时怎么工作

1. 模型根据任务决定是否写代码，先用文件工具把代码保存到当前角色工作区，例如 `workspace/小可/project/app.py`。
2. 调用 `run_workspace_command`，把执行目录设为 `project`，传入命令参数，例如 `["python", "app.py"]` 或 `["node", "app.js"]`。
3. 执行器直接运行这个原文件，把输出、报错和退出码交回模型。模型可以修改原文件并再次运行，不另外保存一份临时代码。
4. 双击模型回复可以查看工具记录。程序是否真正解决问题，要看实际检查结果；模型不能仅凭写完代码就声称成功。

这里采用 AutoGen 本地执行器一类的“文件＋子进程”做法，没有引入 AutoGen 库。所有工具选择仍由聊天模型决定。

## 会不会弹窗口

普通 Python、Node.js、命令行任务在后台运行，隐藏控制台窗口，输出收集到工具结果。代码若主动打开网页、图形应用或窗口，仍可能显示相应界面。

每条命令最长 10 分钟。点击停止或命令超时会结束本次进程及其子进程；命令正常结束后也会清理剩余子进程，因此这个工具目前不能长期托管网页服务器或设备服务。Windows 使用系统自带的进程分组机制清理进程，无需额外配置用户权限。停止不会撤回已写入的文件或已发送的网络请求。

输出保留最后 64,000 字节，超出会标记截取，便于模型看到末尾错误；这个限制不影响代码文件长度。

## 文件与依赖保存在哪里

- 代码与成果保留在角色工作区的当前项目目录，不是执行后就删除的临时文件。
- `.runtime/` 存放该目录的临时文件、缓存和命令运行配置，不需要用户手工维护。
- Python 默认用已安装的解释器；当前执行目录有 `.venv` 时优先使用它。通过 `pip` 或 `python -m pip` 调用包管理器时，没有 `.venv` 就先用已有 Python 离线创建一个。普通 Python 脚本无需先建虚拟环境。
- Node 使用项目自己的 `package.json` 和 `node_modules/`。第一次调用 Node/npm 时，如果当前目录没有 `package.json`，执行器建立只含 `private: true` 的最小配置，防止继承上层 MeloMate 的包配置；已有文件不会被覆盖。模型可按项目需要修改模块类型、脚本和依赖。

例如模型需要 requests，可以在同一个执行目录先运行 `["pip", "install", "requests"]`，再运行 `["python", "app.py"]`。包的下载由这条安装命令触发，不会因为普通代码执行就自动下载。模型必须遵守用户“不下载”等明确要求。需要复用依赖时保持执行目录一致；缺少解释器或虚拟环境损坏时，工具返回原因，不擅自重装。

上述便利规则适用于工具识别的 Python/pip、Node/npm 命令；显式指定其他解释器、安装目录或包管理器时，按该命令自己的配置执行。

## 工作区限制的含义

文件工具以及命令的起始目录受当前角色工作区限制；执行命令使用本机路径，Windows 上使用 Windows 命令。

**本地代码以当前用户权限运行，工作区不是文件权限沙箱。代码能够读写当前用户有权访问的其他目录，也能访问网络。** 执行器不继承后端 API 密钥等环境变量，但这不等于隐藏了当前用户有权读取的文件。普通本地子进程没有额外 CPU、内存或网络隔离。

## 已验证的范围

`backend/tests/test_local_execution.py` 使用真实 Python、Node.js 和 npm 检查保存原文件、错误后修改重跑、项目依赖定位、离线虚拟环境、输出截取、停止、超时、子进程清理和 Windows 隐藏控制台。测试没有下载项目依赖，也没有使用真实聊天 API；模型在具体任务中的完成质量仍需实际对话验证。
