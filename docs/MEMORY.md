# 人设与记忆说明

角色定制只需要一份人设文本，以及聊天后自动产生的一份记忆文本。程序不设置关系发展目标、好感分数、性格成长路线或锁定阶段，也不自动改写人设。表达是否发生变化，由所选模型结合人设、当前对话和历史资料生成。

这改变的是模型每轮看到的上下文，不是训练模型权重，也不能保证模型具有真人的感受、判断或记忆准确度。

## 用户修改的两个文件

| 文件 | 用途 | 谁来修改 |
|---|---|---|
| `characters/profiles/小可.md` | 起始身份与用户提供的人设，目前只有「你叫小可。」 | 用户；程序每轮重新读取，模型没有修改人设的专用工具 |
| `characters/memory/avatar_xiaoke_001/memory.md` | 值得保留的对话事实、经历、过去的表达、约定与待办事项 | 模型按需记录；用户随时可用文本编辑器增删改 |

记忆文件在首次初始化该角色时生成。保存为 UTF-8；可以用普通句子、Markdown 段落或列表，没有必填字段、分类或 JSON 语法。人设不能为空；记忆可以清空。两个文件各最多 32,000 字符。文件过大或编码错误时会报错并保留原文，不会用空白或备份覆盖它。

人设文件在 `characters/profiles/`，记忆文件在 `characters/memory/<角色ID>/memory.md`，其中角色 ID 对应角色 YAML 中的 `conf_uid`。修改最好在本轮回复结束后保存，下一轮生效；开启主动说话时，内容变化也可以提供一次模型回应机会，无需先打开麦克风。已发给 API、显示或播报的内容无法因之后编辑文件而撤回。具体行为见 [会话与真实状态说明](COMPANION.md)。

**局部修改保留其他话题，清空整份记忆才重置上下文。** 新增备注不会清掉历史；只调整列表、标点或记录顺序也不会过滤对话。修改或删除一句时，程序对比前后文本，利用记忆的消息来源和文字匹配，从模型可见的历史中排除相关旧句子，保留同条消息中的其他句子和不相关对话。被修改的原文仍在档案中，界面最多显示最近 120 条。

例如，把「用户叫小林」改成「用户叫小陈」，会处理旧称呼的来源，正在讨论的项目可以继续。局部删改会使旧摘要和正在生成的整理结果失效，避免旧缓存补回内容；重新整理和检索仍能使用未被过滤的对话。通过工具删除最后一条笔记也只处理相关证据，不等于清空所有聊天。

这是上下文过滤，不是磁盘擦除，也不是语义级遗忘保证。有来源 ID 但无法确定句子对应关系时，会排除那条来源消息；没有来源的手写笔记依靠文字匹配，可能漏掉换说法或多过滤相似句子。程序没有调用额外模型猜测删改含义。以后你再次提起某件事，新对话可成为新证据。完整清空 `memory.md` 才会把清空前所有聊天排除出模型上下文。

## 创建新角色

1. 在 `characters/profiles` 新建 `角色名.md` 或 `角色名.txt`，只写人设，例如「你叫阿澄。」。
2. 重新打开页面，刷新角色列表，选中该角色。
3. 使用已经配置好的模型 API 和语音环境开始聊天。无需为新角色编写 YAML、记忆模板或记忆模型配置。

新文本角色继承应用的技术配置，内部记忆 ID 由文件名生成；修改文件内容保留原记忆，改文件名会成为另一角色。同一文件名不要同时放两份不同的 `.md`/`.txt` 人设。

设置中的角色名称和聊天栏中的角色名称统一取人设文件名去掉扩展名：`小可.md` 显示为「小可」，`阿澄.md` 显示为「阿澄」。旧 YAML 中的显示名称不会覆盖这个名称；同名 YAML 的内部记忆 ID 仍保留。

既有 `小可.yaml` 等文件继续保留模型、声音和稳定角色 ID；同名 `.md` 优先于 `.txt`，文本只覆盖人设。小鱼、小薇的既有人设也移到了同名 Markdown，保留这些可选角色原本的设定。程序通用提示词不把它们的性格施加给小可。

## 对话如何受到记忆影响

每轮向聊天模型提供：用户的人设文本、简短的通用能力说明、选中的记忆笔记、较早对话摘要、最近的真实对话和当前输入。

- **最近对话**：从本地档案重新读取，最多约 18,000 字符，不再让内存无限增长；当前用户消息只提供一次。
- **长期笔记**：少量笔记直接带入；较长文件按当前话题的词语匹配和记录顺序挑选，正文预算约 6,000 字符。无关内容不要求在回答里提及。
- **较早摘要**：最多 4,000 字符，由后台整理，属于可丢弃的派生缓存。它不承担第二份人设；局部修改、删除或完整清空记忆会使其失效，新增备注保留它。
- **历史检索**：模型自行调用 `search_memory`，可同时给出主关键词和最多 3 个替代关键词，把同义说法、名称或相关词放在一次调用里。结果合并排序，返回说话者、时间、消息 ID，以及命中前后各一条可用对话片段，帮助理解「那个」「好」等依赖上下文的表达。所有片段共享约 18,000 字符预算。它使用 SQLite 文本索引和中文双字词切分，不是向量语义搜索；替代关键词由聊天模型选择，程序不凭空生成历史证据。

这些预算是字符限制，不是准确的 token 预算；人设、工具定义、当前输入和模型自身的上下文上限仍需考虑。找不到证据时，提示模型说明不确定，程序不会生成虚构的检索命中。消息 ID 校验只能证明来源存在，不能独立判断模型的概括是否准确，因此记忆仍允许人工纠正。

## 如何产生记忆

真实用户输入和可见回复先写入本地档案。至少累计 6 条用户消息后，积累约 6,000 字符的新对话才会触发后台整理；短对话积累到 24 条用户消息也会触发。上一批没有产生笔记改动时，短对话的等待上限延长到 48 条；达到字符阈值仍可提前整理。程序不使用性格关键词判断聊天价值。需要立即保存的事情，模型可直接使用记忆工具，不必等待后台阈值。

后台使用当前聊天模型、服务和凭据，不需要另配模型，也没有下载向量模型。**每次整理会增加一次 API 请求和相应费用**，不阻塞已经完成的回复。失败后的重试冷却从 1 分钟逐步增加到最多 15 分钟，并保存在本地；只有之后发生对话才会再次尝试，不会在应用关闭后重试，也不会每句话都连续请求故障 API。

每次按顺序处理最多 96 条消息、约 24,000 字符，对超长消息只提供片段，原文仍在档案。整理器可以不新增任何笔记。需要更新时，只提交少量有真实消息 ID 的局部改动；这些来源保存在内部索引，用于之后的局部修改与删除。它记录「谁曾经说过或做过什么」，不把玩笑、情绪或单方面要求自动写成固定人格与既定关系。后台不删除笔记，可依据后续对话修正旧内容。

模型也可在当前对话使用三个工具：

| 工具 | 行为 |
|---|---|
| `read_memory` | 读取当前记忆、文件版本和最近消息 ID |
| `search_memory` | 按关键词寻找当前角色可用的历史证据 |
| `edit_memory` | 有依据地新增、精确修改或删除一小段笔记；不修改人设 |

工具接入现有模型调用循环，模型选择时机，记忆工具与其他已接入工具统一允许，不再设置单项许可。程序仍检查当前角色、版本与对话来源。版本已变化、原句不匹配或消息 ID 无效时拒绝写入；整理期间发生人工修改或清空时，旧整理结果会被丢弃。API 失败、超时或输出格式错误不覆盖原笔记，下次对话仍可继续尝试。记忆工具结果不会另存进项目进度日志。

## 人设与主动说话

默认小可只提供名字。移除了旧记忆中的表达适应参数、候选人格推断、固定分类、关系摘要驱动和关键词人格提取；没有自动完成、冻结或强化人格的阶段。过去的偏好只表示过去，后续表达允许不同。

通用提示保留事实与能力边界，例如不编造经历或执行结果、按实际工具能力与项目范围使用工具。没有固定撒娇、安慰、反问、句数或亲密升级要求。用户写进人设的具体性格仍会影响回答。

### 人设是背景与倾向

整份人设按角色已有的资料理解，包括身份、经历、兴趣、习惯、性格、价值观、能力与弱点，不限于外貌或性别。明确的身份与背景用于保持设定一致；描述性的倾向结合当前话题、具体情境和相处经历发挥作用，不是每轮都要展示的行为清单。

例如，“喜欢音乐”不要求主动把所有话题引向音乐；“内向”允许熟悉以后健谈；“坚持自己的判断”也允许被证据说服。程序不要求补全未写的属性，不从单个属性推断整套性格，也不安排改变、完成或冻结人设的阶段。

仍然直接在 `角色名.md` 写普通文本即可，没有新的必填字段或文件。程序在每轮请求中标明“当前角色资料”，并附上统一的使用说明；不会重写用户人设。角色设定的经历与真实聊天、观察、工具行动分开理解，不把设定当作实际行动证明。

记忆的读取、聊天中的记忆编辑工具、后台笔记整理和历史摘要都采用同一原则：保留是谁在什么情境下表达或做了什么，不把单次表现概括成永久性格。例如保存“讨论方案时坚持先验证”，不推断“性格固执，以后都要坚持”。不同场合的表现可以并存，不必自动解释为性格发生改变。反复复述人设或已有笔记不算新的独立证据。

主动说话和文件变化回应也不要求“展示人设”或专门构造情绪；模型可以根据具体情境表达，也可以沉默。已有的人设和记忆原文保留，不会自动清洗旧笔记；如果旧笔记写有不合适的绝对结论，用户仍可直接修改。

这是提示词使用方式的调整，不是消除人设影响或训练模型。若人设正文写有“每句话必须……”等强制命令，所接模型仍可能照做；建议把想描述的特征写成背景事实或倾向。源码测试能检查加载、整理和存储流程，不能证明真实模型永不刻意表演，需要实际对话验证。

主动说话开关保留。定时器和外部记忆、人设变化可以提供一次机会，模型可回复或返回内部静默标记；静默不会出现在字幕、语音或记忆里，也不会算作一次用户没回应的发言。真正说出口的主动回复会保存；程序合成的输入不会假扮用户消息。文字和语音连接均适用，关闭应用后没有后台主动聊天服务。关闭主动说话时，变化等到下一轮用户对话再交给模型。

## 自动文件与旧数据迁移

新角色正常会产生两个主要文件：

```text
characters/memory/<角色ID>/
  memory.md          # 唯一可编辑的长期记忆
  .history.sqlite3   # 自动聊天档案、索引、模型视图、摘要、整理进度及简短变化记录
```

SQLite 运行时可能临时产生 `-wal`、`-shm` 文件；原子写入也会短暂使用临时文件。这些都是程序内部数据，用户不需要编辑。这里的 SQLite 使用 Python 标准库，无需安装数据库服务。档案持续积累，没有自动删除旧消息的保留期限。

数据库保存上一版记忆的文本快照，只用于检测人工差异，不会作为另一份人设或记忆注入模型。旧版数据库会自动补齐内部表；如果从只有文件哈希的版本升级，且在首次加载前已经修改了记忆，没有旧文本可供对比时会保守重置一次上下文，之后使用局部处理规则。

首次加载旧角色时，导入 `short_memory.json` 中现存的对话，以及 `core_memory.json` 中仍有效的事实笔记；标记为已遗忘/失效的条目、旧表达适应参数和推断的关系摘要不作为新的人设导入。原 JSON、`.bak` 和旧备份保持原样，之后不再作为活动记忆源。若已存在用户准备的 `memory.md`，它优先，旧聊天只归档，不给模型作为上下文。无法读取的旧数据会报错，保留原文件。

「删除聊天记录」清空当前角色的活动档案和记忆；不会自动删除旧 JSON 备份、项目文件、任务计划、日志或第三方服务上的记录。若要完整备份，应先关闭应用再复制整个角色记忆目录；不要只复制正在写入的 SQLite 主文件。运行数据被 `.gitignore` 排除，源码只提交文档与空白示例。

## 适用范围与验证

这条完整的本地记忆流程用于 `BasicMemoryAgent`，包括项目默认的 DeepSeek/OpenAI-compatible 聊天路径。Letta、Hume 等外部有状态代理仍可能在服务端保存自己的上下文，不能用本地清空操作保证它们遗忘。

测试覆盖实际本地 SQLite、并发写入、迁移、手工改动、过期整理结果拒绝、上下文重载、后台整理提交、模型工具执行路径与主动静默过滤；模型返回由测试替身提供。没有使用真实 API 或运行完整语音、浏览器端到端测试。源码重构可以去掉强制表达机制，实际自然程度仍取决于所接模型和真实对话表现。

## 思考内容与记忆的区别

回复详情里的思考内容来自 API 的独立返回字段，不是角色说出口的话，也不会作为记忆整理或历史检索的材料。为满足多轮工具协议，程序在已有 `.history.sqlite3` 中自动保存独立的协议缓存；它不增加人设或记忆文本文件，用户无需维护。记忆删改使旧版本缓存失效，正文被过滤或截取时也不会用原协议补回旧内容。详情界面的记录仅在当前页面保留，刷新后不恢复。
